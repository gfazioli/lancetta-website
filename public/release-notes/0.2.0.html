Lancetta 0.2.0

Release notes

The first release. Lancetta is a menu-bar monitor for the coding agents you already run — it shows what is left of your Codex and Claude quota without spending a single token to find out.

What it does

  • Both agents, side by side. Codex's 5-hour and weekly windows read straight from the CLI; Claude's come from the status-line payload it already writes. Neither route asks a model anything: a quota read that costs tokens is the one thing this app will never do.
  • A meter that does not lie. An unknown is never drawn as 0%, and a reading that has gone stale says how old it is instead of pretending to be current — the defect this whole project started from.
  • The island under the notch. Hover the notch for the same numbers, in a shape that grows out of it rather than floating near it. On a Mac without a notch, nothing appears.
  • A window with the history. Overview, Usage, Limits and Processes — including a daily token chart with both agents on it, drawn from Codex's own buckets and from Claude's local transcripts. Neither costs a request.
  • Reclaim orphaned processes. Agent trees outlive their sessions. Lancetta counts them, adds up what they hold, and lists exactly what it will stop before stopping it.
  • Yours to arrange. A colour and the vendor's own mark per agent, the order they appear in, which windows to watch, and a switch that counts down what is left instead of up what is used.
  • A good citizen of the menu bar. Open at login, an optional Dock icon, and updates it checks for itself from here on.

Install

  1. Download Lancetta-0.2.0.dmg
  2. Open it and drag Lancetta into Applications
  3. Launch it normally — it is signed with an Apple Developer ID and notarized by Apple, so there is no Gatekeeper detour

It lives in the menu bar and, at rest, puts nothing in the Dock.

Requirements

macOS 15.0 or later. Apple silicon or Intel is irrelevant to it; what matters is having Codex or Claude Code installed — and if you have neither, it says so in a sentence that tells you what would change that, rather than showing an error.

Why v0.2 and not v0.1

The roadmap's v0.1 was the quota. The memory half — the process reaper — was planned for later and arrived in the same build, along with the window and the token chart. The version number follows what shipped.
