Lancetta 0.63.0

Release notes

Maintenance reads more of what Claude Code loads

  • The rules of subfolders, which Claude Code reads when a session works there, are listed with the folder they belong to.
  • Your organization's managed rules and the instructions its policy carries are listed and counted in each launch they join, the way Claude Code loads them.
  • Rules are matched as Claude Code matches them, from the folders above a repository into the repositories below it, linked worktrees included.

Checks that say what really happens

  • A rule behind a link Claude Code doesn't follow no longer vanishes from the list: it is listed as ignored, with a finding that says where the link leads.
  • An import out of a repository is worded by who reads the file: in a committed one, everyone who opens the repository is asked once; in one only you have, it is judged as your own sessions read it.
  • More programs are checked: your organization's own hooks, status line and helpers, its policy helper, file suggestions, the subagents' status line, the background sessions' launcher and gcpAuthRefresh. Each finding lands in the file that names the program.
  • MCP servers your organization keeps from starting are no longer flagged, and nothing is ever offered to fix inside the organization's policy.

Storage, always there

  • The Storage card stays on Maintenance once it has looked, and says All clear when nothing can go.

Fixes

  • A file a CLAUDE.md imports no longer reads as uncommitted when git tracks it.
  • A session handed a rule or a CLAUDE.md of a folder above now starts in the folder that owns it.
  • One file linked into several repositories is no longer reported as duplicated paragraphs.
