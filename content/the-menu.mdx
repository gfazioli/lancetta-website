# The Panel

One card per agent, one row per window.

![The Lancetta panel: how fresh the numbers are across the top, then Claude Code and Codex, each window with its bar and the time it resets. Claude’s lines say where each window ends at the current rate; Codex, spent for the week, shows the free reset it holds, with a Use… button](/screenshot-menu-dark.png)

It is a panel rather than a menu, and that is not decoration. A macOS menu's
background belongs to the system: its rows can be anything, the surface behind
them cannot. Lancetta's own colours are a deep navy, and the menu was the one
place in the app that was system grey. It is also narrower — a menu reserves a
column for keyboard shortcuts that nothing can reclaim, so the same content used
to need 466 points and now needs 380.

It is always dark, like the window, whatever appearance your Mac is in.

## The card header

```
Claude · max 20×                    seen 7s ago
```

- **The mark and the name** — the agent this card is about. The marks are the vendors' own artwork; one switch in [Settings](/docs/settings#appearance) replaces them with neutral system symbols.
- **The plan** — read from the account itself rather than typed into a setting, so it cannot drift out of date.
- **The freshness marker** — how long ago this reading was taken, shown only when it trails the panel's own **Updated … ago** line by more than a minute and a half. The panel has one clock, at the top; a card adds its own age only when that clock would be wrong about it. Codex can be asked, so it keeps up. Claude, once connected, is asked too — at most once a minute, and straight away on Refresh now — so it keeps up while the account answers; if the account asks for a pause, the last reading stays on the card with its age. Through the status-line file instead, the reading moves only while a Claude Code session is open, so after an idle evening the card says *seen 3h17m ago* under a header saying *Updated 5s ago* — and the gap between the two is the point. That asymmetry is real and the panel shows it rather than smoothing it over — see [How it reads each agent](/docs/how-it-reads). A Claude card still on that route also says so under its bars — *From the status-line file, which moves only while a Claude Code session is open* — with a **Connect Claude Code…** button beside the sentence, because a Mac wired that way before the account route existed was never told there was a better one.

## The rows

```
 4%   5h   ▓░░░░░░░░░░░░░░░   ↻ 3h29m
           4% in 1h30m · at this pace 13% by reset
55%   7d   ▓▓▓▓▓▓░░░░░░░░░░   ↻ 4d06h
100%  Fable ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓   ↻ 4d06h
```

- **The percentage** — how much of that window is spent, or how much is left, depending on [one setting](/docs/settings#general). The bar is filled with whichever number is on screen, never with its opposite.
- **The window** — `5h` is the rolling five-hour bucket, `7d` the weekly one. A row carrying a **model's name** instead is a weekly limit that belongs to that model alone, counted separately from the two above and sent by your account under that name. It appears only when your account has one and only once it has been used; see [How it reads each agent](/docs/how-it-reads#a-window-one-model-keeps-to-itself).
- **The bar** — the same number, drawn, so a glance is enough. It is tinted with the colour you gave that agent.
- **The reset** — when this window rolls over. This is the number that makes the percentage actionable: 80% with four hours to go is a different afternoon from 80% with ten minutes to go.

### A free reset

```
100%  7d   ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓   ↻ 7h14m
           spent · until it resets, or a free reset
↺ 1 free reset · until 22 Oct                  Use…
```

When Codex's account grants you a free reset of its windows, the card says so under its bars, with the day it lapses; point at the row for what the account calls it and when it was granted. **Use…** is there only while a window has something to reset, and it never spends anything by itself: it asks first, and the question puts two dates side by side — when each window would come back **on its own**, and when the credit **lapses** — with **Cancel** as the default. A week that comes back by itself this afternoon and a credit that lasts a month are two facts, and the question shows both rather than deciding for you.

While a credit is in hand, a spent window no longer says *nothing more until it resets*, because that has stopped being true. If the answer to a spend is lost on the way back, trying again repeats the same request, so it can never spend a second credit. After a reset the card shows the new numbers as soon as the next reading lands.

Only Codex has these. Claude's account grants no free resets — what Claude calls usage credits is paid extra usage, and Lancetta does not deal in money.

### How a length of time is written

Every duration in Lancetta — a reset, an age, a window's elapsed time — is written
the same way: **two units, the larger first, and the larger one is the largest that has
reached 1.**

```
45s     59m     1h04m     23h59m     1d     1d05h     6d23h
```

The second unit is dropped when it is zero, so a reset exactly two days out is `2d`
rather than `2d00h`. Nothing is ever rounded up: a countdown that overstates would
promise a return that has not happened.

Up to ninety seconds it counts in seconds, which is the one place a smaller unit is
*more* honest than a larger one: `75s` says something `1m` does not, and it costs you
no arithmetic to read.

The agents appear in **the order you put them in**, set by dragging in [Settings → Agents](/docs/settings#agents). Every surface reads the same order.

## The pace line

Under the bar it belongs to, a caption saying where that window ends at the rate
you are going:

```
55% in 2 days · at this pace full by Wednesday afternoon
```

This is the part the percentage cannot tell you. The number is on your menu bar
all day, so you already know when it is getting low; what you cannot see is
whether **this** pace empties the window before it resets. The line is always
there, in the same place, and the only thing that changes is its colour: it turns
orange when the window would run out early. A line that only ever appears in
trouble is a line nobody has learnt to read by the time it matters.

It comes from the series Lancetta keeps of its own readings, so it costs nothing
extra to say. Two things it will not do. It will not speak about the weekly
window until this Mac has watched that window actually turn over at least once —
what a bucket does at its own edge is a fact about your account, not an
assumption worth shipping. And if you want the number and nothing else, one
switch in [Settings](/docs/settings#general) keeps the line for the case where
there is something to do about it and hides it otherwise.

When a window has refused you outright, the card says so under the rows, in the
window's own name.

## Processes

```
14 Codex trees · 2.68 GB          Reclaim 2.24 GB
```

*(Those are the figures from the census that produced this feature, not a mock-up.)*

One strip for the background trees the agents have left running, and a
**Reclaim** button when some of them are serving directories that no longer
exist. It is drawn only when there are trees to report — a permanent row of
zeroes teaches you to stop reading that part of the panel. It shows you the list
before it stops anything on it. See [The processes they leave behind](/docs/memory).

## Limits

When a window refuses you, **that window is the one you see**. Lancetta does not average the buckets into one comfortable total — an average across a refused bucket and a healthy one lands somewhere reassuring and tells you nothing about why the last request failed. In the menu bar the refusal is named: the refusing agent's cell shows its mark beside a dead lamp — black with a red edge — its window at 100%, and the time that window comes back, and the other agents keep their turns — a block on Codex is not information about Claude.

When an agent cannot be read at all, the card says so in one sentence. A situation that is not a fault, such as Codex not being installed or Claude Code not signed in, is described calmly with what would change it, and with the one button that would change it. A fault is drawn red, and **Why, and what to do…** opens a window naming the code, the likely cause and the fix beside the raw evidence, with a report to copy into an issue. Every code is listed on the [Troubleshooting](/docs/troubleshooting) page.

## Unknown is not zero

A window Lancetta has no reading for is drawn as unknown. It is never drawn as `0%`, and a reading whose reset time has already passed is not silently treated as an empty window — a rolled-over window does not mean nothing was spent since.

## The rest of the panel

The strip across the top is the panel's own toolbar:

- **Updated 14s ago** — how long since Lancetta last read an agent, and, clicked, **Refresh now** (⌘R). It asks every agent that can be asked: Codex, and Claude once it is connected. Through the status-line file instead, the Claude card is refreshed by the next session that renders one, not by this — and the card says so, with the Connect button that would change it. It never raises the keychain dialog: that belongs to Connect alone. It spins while the read is on its way and the panel stays open, so you can watch the numbers move; it turns amber once three polls, and at least three minutes, have gone by without a reading.
- **Update** — a button naming the new version, drawn only when one is out. It opens the update prompt. The rest of the time it is not there, because a button whose answer is nearly always "you are up to date" teaches you to stop looking at it.
- **Settings** (⌘,) — the gear.
- **The pin** — see below.

Along the bottom, **Open Lancetta…** (⌘O) — the window: usage over weeks, both agents in detail, and the process list; see [The Window](/docs/the-window) — and **Quit Lancetta** (⌘Q).

**Right-click** the menu-bar item for the classic menu with every command in it: Refresh Now, Open Lancetta…, Settings…, Check for Updates…, About Lancetta and Quit Lancetta. It works with the panel pinned too.

The panel closes when you press Escape, click anywhere outside it, or click the
menu-bar item again.

### Pinning it

The **pin** in the top-right corner keeps the panel on screen. Pinned, none of those
three things closes it — not a click elsewhere, not another window taking the keyboard,
not the pointer leaving the item — and neither does choosing Settings or Open
Lancetta inside it, which open their window beside it. It stays in front of
whatever you are working in, and you can drag it away from the menu bar to wherever
suits.

**Escape still closes it.** The pin is remembered, so it opens pinned next time.

### Opening it without clicking

If you would rather not click at all, **Settings › General › Menu › Open the menu on
hover** opens the panel when you point at the item. It is off unless you turn it on,
because a panel that opens while the pointer is merely crossing the menu bar on its way
somewhere else is an interruption for everyone who did not ask for one.

Opened that way the panel does not take the keyboard — moving a mouse should not pull
the focus out of what you are typing — so Escape and ⌘R are not live until you click the
item, which hands the panel the keyboard and leaves it open until you click away. The
controls work under the pointer regardless: clicking **Updated … ago** does refresh.

## The menu-bar item itself

```
[mark] [lamp] 28% · ↻1h44m
```

What sits in the menu bar is configurable per agent: its mark, its percentage, its reset, in any combination. With more than one agent in the bar they take turns, cross-fading, and the item holds a fixed width at the widest of them so the items beside it never shift.

**The lamp is always there, and it is the part you do not have to read.** A small glass bead between the mark and the numbers, in one of four colours:

| | |
| --- | --- |
| **green** | up to 50% of the window spent — work |
| **amber** | over 50%, up to 80% — still yours, but it is going |
| **red** | over 80% — finish what you are on |
| **black, red edge** | refused, or nothing left. Unusable until it comes back |

A window nobody has managed to read yet shows a **grey** bead rather than a green one. An unknown is not an empty quota, and this app exists because a status line once drew one as the other.

The bead reads what is **spent**, whichever way round you asked to see the number: if you have the item showing what remains, `3%` on screen is a red lamp, not a green one.

A refused agent reads **100%** — or `0%` if you are showing what remains — so its cell has the same shape as the cells beside it:

```
[mark] [green]  19% · ↻1h23m
[mark] [black] 100% · ↻1d01h
```

The number is not the last reading: the account has said there is nothing left, which is more recent than whatever the last poll measured. It follows your fields like any other cell — switch the percentage off and a refusal has none either. The reset does not: a block raises exactly one question, and that is it.

An agent can be watched and still kept out of the bar — the menu bar is narrow, and an agent worth a card is not always worth the width. The lamp, though, does not follow the fields: switch the mark and the percentage off and the bead is still there, because it is the whole of the question *can I use this*.
