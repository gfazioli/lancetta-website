# The memory half

Quota is what the agents cost you while you are working. This is what they cost you afterwards.

## What accumulates

A coding agent starts a small background tree for each working directory it operates in — a broker, a server, a host process. One chain per directory.

They exit when they are told to. The trouble is what happens when nobody tells them:

- The broker has **no idle timeout**. Nothing closes one whose socket has had no client for a day.
- Cleanup does exist — there are session-end hooks that resolve the broker and shut it down. But if the **working directory was deleted before the session ended**, the state that would resolve it went with the directory, and the shutdown is never sent. A session killed hard enough that its end hook never ran has the same outcome.

Either way the result is certain: **nothing will ever reap them.**

They also hide well. The broker is a `node` process and shows in Activity Monitor under that generic name, so what looks like twenty-eight processes is really forty-two. And a tree is deeper than its own documentation says: the shape published for it is three processes, and a real one measured **eleven descendants holding 392 MB**, because the server had gone on to spawn helpers of its own. Lancetta walks the parent table rather than trusting a fixed depth.

## What that cost, once, on one Mac

| | |
|---|---|
| Processes | 28 |
| Resident memory | 2.68 GB |
| Trees whose working directory no longer existed | 12 of 14 |
| Oldest still alive | 1 day, 8 hours |

Reaped: **28 → 4 processes, 2680 → 436 MB.** 2.24 GB returned.

## The rule

**A broker whose working directory no longer exists on disk.** On the fourteen candidates measured, that predicate gave **twelve true positives and no false positives** — the two it spared were live.

Three things keep it that way, and each one is a way the obvious version would have been wrong:

- **A broker with no working directory in its arguments is never an orphan.** Unknown is not gone, and that is the one place where being wrong ends somebody's running session.
- **The directory is read to the end of its argument, not to the first space.** A folder whose name contains a space would otherwise be truncated to a path that does not exist — and *the path does not exist* is precisely the orphan test. The naive parse turns a live tree into a target.
- **Stopping one means signalling the broker, never its children.** Its own handler tears the tree down cleanly; measured, the whole tree was gone in under a tenth of a second and the live trees were untouched.

## What it looks like

The menu grows a **Processes** line whenever there is something to say — how many trees, what they hold, and a **Reclaim** item when some of them are orphaned. It is drawn only when trees are running: a permanent row of zeroes teaches you to stop reading that part of the menu.

The [window's Processes pane](/docs/the-window#processes) has the whole list: each tree, the directory it was started for, what it is holding, how many children it has.

And one rule that is not negotiable: **it shows you the list before it stops anything on it.** The entire point of the feature is that you can finally see what you could not. The confirmation puts **Cancel** on the default key and gives Reclaim no keyboard shortcut at all, which is the arrangement an irreversible action wants.
