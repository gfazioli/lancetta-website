# Privacy

Lancetta has no account, no server of ours and no telemetry. **Nothing you do in it is reported to anyone**; the few requests it makes are listed under [What it sends](#what-it-sends).

## What it reads

- **Codex** — an account read, asked of the Codex CLI on your machine over its own local interface; the CLI fetches the figures from OpenAI with its own sign-in. It returns your rate-limit percentages, reset times and plan, how many free resets the account holds (and, once per new count, what each is called and when it lapses), and — separately, when the window is open — your token totals per day. That read does not return the contents of any session.
- **Claude Code** — once you connect it, the sign-in Claude Code keeps in your keychain, read and never renewed (the refresh token in the same item is never kept or used), and with it one account read: your rate-limit percentages and reset times. Or, if you set that up instead, one file on your disk written by your own status-line command.
- **Claude Code's transcripts, for the token chart** — the files Claude Code keeps under `~/.claude/projects`, searched for the usage block on each reply. Lancetta keeps the message's id, its time and its token counts, and nothing else: the text of your prompts and answers is never extracted, stored or sent. Only the files that changed since the last look are read again.
- **Your plan** — from the same account reads, or, when Claude Code is followed through its status line, from the account metadata Claude Code keeps on your Mac.
- **The process table** — the same list `ps` gives you, to find the background trees the agents have left running. It reads their command lines, argument by argument, which is where the working directory each one was started for lives. That directory is shown to you in the window; it is never sent anywhere.
- **Your agents' instruction files, for [Maintenance](/docs/maintenance)** — CLAUDE.md, AGENTS.md, GEMINI.md, rules, skills, commands, subagents, settings and memory, in each repository Claude Code or Codex has worked in and the folders above it, in `~/.claude`, `~/.codex` and `~/.gemini`, and your organisation's managed CLAUDE.md in `/Library/Application Support/ClaudeCode` when there is one. Which repositories those are comes from the transcripts under `~/.claude/projects` and from Codex's record of its sessions in `~/.codex`, of which it reads only the folder each session started in (Codex's, those of the last 30 days). It runs `git` in those repositories to know what is committed, reads Codex's record with macOS's own `sqlite3`, read-only, and asks your own Claude Code (`claude agents`) for the background sessions it has finished with. The files are read to be counted and checked, on this Mac; what is in them goes nowhere unless you copy the findings or hand them to Claude Code.
- **Your Claude Code sessions, for [Sessions](/docs/sessions)** — at every refresh while Claude is watched, Lancetta asks your own Claude Code for the list of its sessions (`claude agents`), which starts none and changes none: each session's name, the folder it runs in, where it stands, when it started, and the identifiers Claude Code gives it. It is read on this Mac and kept in the wall below; none of it is sent anywhere.
- **Your Codex sessions, for [Sessions](/docs/sessions)** — at every refresh while Codex is watched, Lancetta asks Codex's own background service on your Mac which sessions it has open, through your own Codex (`codex app-server proxy`), a local, read-only question that starts none and changes none. Lancetta keeps each session's id, where it stands, its name, the folder it runs in and when it was created. A session with no name comes with its first message, of which Lancetta keeps the first line, cut at 80 characters, as its name, and nothing else. It does not ask for the conversation, opens no transcript of Codex's, and installs nothing into Codex. It is read on this Mac and kept in the wall below; none of it is sent anywhere.
- **The effort your agents are set to, for the [suggestions](/docs/suggestions)** — `effortLevel` in `~/.claude/settings.json` and `model_reasoning_effort` in `~/.codex/config.toml`, so a suggestion can say which effort it would lower. Read, never changed.

## What it does

A few things in this app are not read-only, and each one happens only after you have seen what it will do and said yes.

**Reclaim** stops background processes. Four rules bound it, and all four are in the code rather than in this paragraph:

- only a Codex broker **whose working directory no longer exists** is ever a candidate — one whose directory is unknown, or in a folder Lancetta is not allowed to look into, is never treated as gone;
- it **looks again just before it stops anything**: a broker is signalled only if it is still the same broker for the same missing directory;
- it **shows you the list first**, and the confirmation puts Cancel on the default key;
- it signals the broker, which closes its own tree. It does not touch anything else.

**Use… on a free reset** spends one of your Codex reset credits, which cannot be given back:

- it is offered only while the account says you hold one and a window has something to reset;
- the question names the credit, when each window would come back on its own and when the credit lapses, and puts Cancel on the default key;
- it is asked through the Codex CLI on your Mac, the same way every Codex reading is, and a retry after a lost answer repeats the same request instead of spending a second credit.

**A Maintenance fix** writes to your own files: an import added or corrected in an instruction file, or a new CLAUDE.md that imports AGENTS.md; a line at the end of a MEMORY.md; an entry in a `.gitignore` with `git rm --cached` beside it; a new `.gemini/settings.json`; in a settings file or a `.mcp.json`, a program's path put in quotes or a variable written the way Claude Code fills it in; or execute permission on a script that a hook, the status line, a helper or a server runs. It shows every change before anything is written, each line it would add or remove and the permission it would give, writes only on **Apply**, and only if every file is still exactly what the preview showed; if anything fails halfway, everything it changed is put back.

**Move to Trash…** moves a file no agent uses to the Trash, where the Finder can put it back. It is offered only for such files, and the file is read again just before it moves.

**Removing background sessions** asks your own Claude Code to do it, one `claude rm` per session, after a confirmation that names what it frees. Claude Code refuses on its own to remove a session that holds work not pushed.

**Open, on a session in [Sessions](/docs/sessions)**, opens that session in your terminal, as `claude attach` would for a Claude Code background session and `codex resume` for a Codex session, through a one-time script in the temporary folder that deletes itself. **Done**, **Put back** and **Rename…** change only Lancetta's own wall: the session in Claude Code or Codex is never closed, stopped or renamed.

**Settings › General › Command line** writes outside Lancetta's folder, and only on a click: **Install…** makes a link named `lancetta` to Lancetta's own binary, in `~/.local/bin` when that folder exists, otherwise in `/usr/local/bin` after macOS asks for an administrator's password; each **Agent Skill** row writes one `SKILL.md`, into `~/.claude/skills/lancetta` or Codex's `skills/lancetta`. Neither replaces a file Lancetta did not write, and **Remove** deletes only Lancetta's own link or `SKILL.md`. The skill is text an agent reads; it runs nothing by itself. See [The command line](/docs/command-line).

**Fix with Claude Code** and **Fix with Codex** start your own agent in Terminal, in the file's repository, with a first message Lancetta wrote, through a one-time script in the temporary folder that deletes itself. From then on it is your session: Claude Code, in plan mode, edits nothing until you approve its plan; Codex is asked to wait for your OK, in a sandbox that writes only in the repository and the file's own folder.

## What it writes

Of its own, six things, all on this Mac (what a Maintenance fix, Move to Trash, a removed session or the command line's rows change in your files is the action you chose, under [What it does](#what-it-does)):

- **Your own preferences** — the refresh interval, the colours and order you gave the agents, which ones are hidden, what each one shows in the menu bar, the notch switch, whether you count up or down, and how many free resets it last saw, so that a new one can be announced — in the standard macOS preferences location for the app.
- **The series of its own readings**, in `~/Library/Application Support/Lancetta/history.jsonl`: for each reading, when it was taken, which agent, both windows' percentages and resets, the plan, the route it arrived by and the free resets held. Each line also carries a short salted hash of the account, so two accounts' series never mix; the salt is in `history.salt` beside it. Past 4 MB the series rolls over into `history.1.jsonl`. It is what the pace line reasons from, and it never leaves your Mac.
- **A cache of Claude's token counts**, `claude-usage-cache.json` beside it: per transcript file, its size and date and the tokens of each reply by day, so the chart does not re-read every transcript each time. File paths and numbers, never text.
- **The last reading of each agent**, `usage.json` beside it: what [`lancetta usage --json`](/docs/command-line) prints — each agent's numbers, the plan, the route they came by, the problem when there is one, whose detail can name a file in your home folder or quote the error an agent returned, and what Lancetta suggests now, in English. Rewritten after every read; nothing reads it but the `lancetta` command, the agents you give the Agent Skill or a hook to, and whatever else you point at it.

- **The wall of [Sessions](/docs/sessions)**, `sessions.json` beside them: each session's post-it, with whose session it is, the name its agent gives it or the one you gave it, the path of the folder it runs in, its agent's identifiers for it, where it stands, when it started, whether you called it done, and how long Lancetta saw it working and waiting.
- **The record of concluded sessions**, `sessions-history.jsonl` beside it: a line each time a session is concluded or put back, with whose session it was, its name, the name of its folder, its start, its end, who ended it, and how long Lancetta saw it working and waiting. It only grows, and [Settings → Privacy](/docs/settings#privacy) clears it.

Deleting that folder costs you the series the pace line learns from and the record of your sessions; the cache and the last readings are written again on the next read, and the wall at the next listing.

## What it sends

There is no analytics call and no crash reporter. Lancetta has never had either and will not get one.

Every request it makes is named here:

- **The Claude account read**, once you connect it: the same request Claude Code's own `/usage` makes, to Anthropic, carrying the sign-in Claude Code keeps and the app's version. It stops the moment you disconnect.
- **The Codex readings**, while Codex is shown: Lancetta asks the Codex CLI on your Mac, and the CLI fetches your rate limits from OpenAI with its own sign-in, as it does for itself. Hide Codex in Settings to stop them.
- **The update check**, which fetches a signed release feed from this website and carries the app's version. Both automatic forms of it are **off until you turn them on** in [Settings → Updates](/docs/settings#updates): a silent check when the app starts, and the update framework's own schedule, which asks you once, on the second launch. **Check for Updates Now…** makes the same request when you ask for it. When there is a new version, its notes come from this website and its download from GitHub.
- **The About window** shows a sponsor's picture, which is loaded from GitHub.

That is the whole list. There is no account, no server of ours, and nothing that reports what you did.

**Fix with Claude Code** and **Fix with Codex** are not on it because they are not requests Lancetta makes: each hands a prompt to your own agent, which then works as it always does, with your sign-in, and sends what any session of yours sends.

## Why reading costs nothing

Not a privacy point exactly, but it is usually the next question: Lancetta never sends a prompt to a model to find out how much quota is left. That would be a model turn, it would cost tokens on every poll, and it would send something. See [How it reads each agent](/docs/how-it-reads).

## This website

- **No cookies of ours, no cross-site tracking.** The site sets none, and does not follow you across other sites.
- **Visit statistics.** Visits are counted by privacy-friendly analytics that use no cookies and build no profile of you: pages viewed, the referring site, country, and browser or device type, in aggregate. Visits are grouped by a hash of the request that is discarded after 24 hours.
- **Server logs.** The hosting provider that serves these pages, and the app's update checks, processes your IP address and the details of each request to deliver the site and keep it secure; the request logs we can see are kept for one day.
- **Pictures from other services.** The home page shows a launch badge loaded from Product Hunt, and the sponsor pictures at the bottom of every page are loaded from GitHub. Those services therefore see your IP address and the details of the request, including the site it came from, and Product Hunt's server sets a cookie on its own domain as it sends the badge: `__cf_bm`, Cloudflare's protection against bots, which expires after 30 minutes of inactivity. Downloads also come from GitHub.
